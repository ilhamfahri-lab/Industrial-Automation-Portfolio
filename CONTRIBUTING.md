# Contribution and Maintenance Guide

Keep this portfolio easy to review, reproducible, and technically honest.

- Use focused commits with prefixes such as docs:, feat:, test:, fix:, and chore:.
- Record software versions, assumptions, test methods, expected and actual results, and evidence links.
- Never invent test outcomes or describe planned work as completed.
- Use synthetic or sanitized data.
- Do not publish secrets, vendor license material, confidential plant data, or files you are not allowed to redistribute.
- Use the [Portfolio Quality Standard](docs/PORTFOLIO-STANDARD.md) before marking any project tested or complete.

For a completed project, provide a problem statement, requirements, design, implementation artifacts, tests, evidence, limitations, and reproduction steps.
