# Portfolio Quality Standard

Each completed project should contain:

1. Problem statement and intended user.
2. Testable requirements and explicit assumptions.
3. Design artifacts appropriate to the project: architecture, I/O list, diagrams, data model, or network plan.
4. Implementation files or representative exports, with exact software versions.
5. Test cases with preconditions, steps, expected result, actual result, pass/fail status, and evidence.
6. Real, captioned screenshots or a short demo.
7. Limitations, unresolved defects, and reproducible setup instructions.

## Evidence rules
- Capture normal operation, one or more meaningful faults, and recovery behavior where applicable.
- Link claims such as “interlock tested” to the relevant test record.
- Label synthetic data and simulated equipment.
- Never invent test results.

## Safety and professional boundaries
- Simulation is not proof of a safety-rated system.
- Project 04 is not a certified electrical design or data-center commissioning package.
- Do not connect experiments to live plant networks or equipment without authorization and qualified supervision.
- Do not publish credentials, license keys, confidential data, or proprietary material.
